● AI Algorithm Explanation - src/utils/ai.js

  This file implements a three-tier AI system for the Gomoku game, ranging from random/simple play to full Minimax search with
  Alpha-Beta pruning.

  ---
  High-Level Overview

  The AI has three difficulty levels:
  ┌────────┬────────────────────────┬───────────────────────────────────────────────────┐
  │ Level  │ Strategy               │ Behavior                                          │
  ├────────┼────────────────────────┼───────────────────────────────────────────────────┤
  │ Easy   │ Random + basic offense │ 30% random, only considers attack scores          │
  ├────────┼────────────────────────┼───────────────────────────────────────────────────┤
  │ Medium │ Heuristic evaluation   │ 15% chance of "mistake", balances offense/defense │
  ├────────┼────────────────────────┼───────────────────────────────────────────────────┤
  │ Hard   │ Minimax + Alpha-Beta   │ Full search algorithm with look-ahead             │
  └────────┴────────────────────────┴───────────────────────────────────────────────────┘

  ---
  Core Components

  1. Position Evaluation (evaluatePosition - lines 11-55)

  This function scores how valuable a position is for a player by analyzing all four directions.

  Algorithm:
  For each of 4 directions (horizontal, vertical, 2 diagonals):
    1. Count consecutive pieces in positive direction (up to 4 steps)
    2. Count consecutive pieces in negative direction
    3. Count "open ends" (empty spaces at ends of the line)
    4. Score based on pattern

  Scoring Table:
  ┌────────────┬───────────┬──────────────────────┐
  │ Pattern    │ Open Ends │ Score                │
  ├────────────┼───────────┼──────────────────────┤
  │ 5-in-a-row │ any       │ 100,000 (winning)    │
  ├────────────┼───────────┼──────────────────────┤
  │ 4-in-a-row │ 2 open    │ 10,000 (unstoppable) │
  ├────────────┼───────────┼──────────────────────┤
  │ 4-in-a-row │ 1 open    │ 1,000                │
  ├────────────┼───────────┼──────────────────────┤
  │ 3-in-a-row │ 2 open    │ 1,000                │
  ├────────────┼───────────┼──────────────────────┤
  │ 3-in-a-row │ 1 open    │ 100                  │
  ├────────────┼───────────┼──────────────────────┤
  │ 2-in-a-row │ 2 open    │ 100                  │
  ├────────────┼───────────┼──────────────────────┤
  │ 2-in-a-row │ 1 open    │ 10                   │
  └────────────┴───────────┴──────────────────────┘

  Example: If placing a piece creates ".XXX." (3 in a row with 2 open ends), it scores 1,000 points.

  ---
  2. Candidate Move Generation (getCandidateMoves - lines 84-114)

  Instead of evaluating all 225 positions (15x15), this optimization only considers positions near existing pieces.

  Empty board? → Return center (7,7)
  Otherwise → Return all empty cells within 2 squares of any piece

  Performance impact: Reduces search space from O(225) to typically O(20-50) positions.

  ---
  3. Win Detection (checkWinner - lines 368-391)

  Checks if the last move created 5 consecutive pieces in any direction.

  For each direction:
    Count same-color pieces in positive direction
    Count same-color pieces in negative direction
    If total >= 5: return true

  ---
  Difficulty Implementations

  Easy Mode (findEasyMove - lines 197-232)

  // 30% random move
  if (Math.random() < 0.3) return random candidate

  // 70% simple offense-only evaluation
  score = attackScore + randomBonus
  if near center: score *= 1.1

  Characteristics:
  - Ignores defense completely
  - High randomness makes it beatable
  - Good for beginners

  ---
  Medium Mode (findMediumMove - lines 241-274)

  // 15% chance to make a "mistake" (use easy logic)
  if (Math.random() < 0.15) return findEasyMove()

  // 85% balanced evaluation
  score = attackScore + (defenseScore * 0.9)
  if near center: score *= 1.2 to 1.5

  Characteristics:
  - Balances offense and defense
  - Occasional mistakes make it feel human
  - Position-aware (prefers center)

  ---
  Hard Mode (findHardMove - lines 283-336)

  This uses the Minimax algorithm with Alpha-Beta pruning.

  Step 1: Immediate Win/Loss Check
  // Can AI win right now?
  for each candidate:
    if placing piece wins: return that position

  // Must block opponent winning?
  for each candidate:
    if opponent would win: return that position

  Step 2: Minimax Search
  // Sort candidates by heuristic score (better pruning)
  scoredCandidates = sort by (attackScore + defenseScore)

  for each top 12 candidates:
    simulate placing piece
    score = minimax(board, depth=2, alpha, beta, isMaximizing=false)
    undo placement

    // Position bonus
    if near center: score *= 1.1 to 1.3

    track best move

  ---
  Minimax Algorithm Deep Dive (lines 127-188)

  The Minimax algorithm is a recursive search that simulates future moves.

  Minimax(board, depth, alpha, beta, isMaximizing):

    1. TERMINAL CONDITIONS:
       - If AI can win: return +1000000 + depth
       - If human can win: return -1000000 - depth
       - If depth=0: return heuristic score

    2. MAXIMIZING (AI's turn):
       maxEval = -∞
       for each candidate (top 8):
         place piece
         eval = minimax(depth-1, minimizing)
         undo placement
         maxEval = max(maxEval, eval)
         alpha = max(alpha, eval)
         if beta <= alpha: break  // PRUNE!
       return maxEval

    3. MINIMIZING (Human's turn):
       minEval = +∞
       for each candidate (top 8):
         place piece
         eval = minimax(depth-1, maximizing)
         undo placement
         minEval = min(minEval, eval)
         beta = min(beta, eval)
         if beta <= alpha: break  // PRUNE!
       return minEval

  Alpha-Beta Pruning Explained:
  - alpha: Best score AI can guarantee (starts at -∞)
  - beta: Best score human can guarantee (starts at +∞)
  - When beta <= alpha: We've found a move that the opponent would never allow, so stop searching this branch.

  Why it works:
  If AI has already found a move worth 1000,
  and we're evaluating a branch where human can force score to 500,
  we don't need to explore that branch further - AI won't choose it.

  ---
  Performance Optimizations

  ┌─────────────────────┬────────────────────────────┬──────────────────────┐
  │ Optimization        │ Location                   │ Impact               │
  ├─────────────────────┼────────────────────────────┼──────────────────────┤
  │ Candidate filtering │ getCandidateMoves          │ ~80% fewer positions │
  ├─────────────────────┼────────────────────────────┼──────────────────────┤
  │ Move ordering       │ scoredCandidates.sort()    │ Better pruning       │
  ├─────────────────────┼────────────────────────────┼──────────────────────┤
  │ Width limiting      │ slice(0, 8) / slice(0, 12) │ Faster search        │
  ├─────────────────────┼────────────────────────────┼──────────────────────┤
  │ Depth limiting      │ depth = 2                  │ Prevents long waits  │
  ├─────────────────────┼────────────────────────────┼──────────────────────┤
  │ Early termination   │ Win/block check first      │ Instant decisions    │
  └─────────────────────┴────────────────────────────┴──────────────────────┘

  ---
  Complexity Analysis

  ┌────────┬───────────────────────────────────┬────────────────────┐
  │ Level  │ Time Complexity                   │ Space Complexity   │
  ├────────┼───────────────────────────────────┼────────────────────┤
  │ Easy   │ O(n) where n = candidates         │ O(1)               │
  ├────────┼───────────────────────────────────┼────────────────────┤
  │ Medium │ O(n)                              │ O(1)               │
  ├────────┼───────────────────────────────────┼────────────────────┤
  │ Hard   │ O(b^d) where b=branching, d=depth │ O(d) for recursion │
  └────────┴───────────────────────────────────┴────────────────────┘

  For Hard mode with typical values (b=12, d=2):
  - Without pruning: ~144 positions evaluated
  - With pruning: typically ~50-80 positions evaluated

  ---
  Key Design Decisions

  1. Depth=2: A balance between intelligence and performance. Higher depths (3+) would make the AI stronger but slower.
  2. Position bonus for center: The center is strategically valuable in Gomoku, so the AI slightly prefers central moves.
  3. Defense weight = 0.9: AI prioritizes offense slightly over defense, making it more aggressive.
  4. Medium mode's "mistake" probability: Makes the AI feel more human and less robotic.

  ---
  Potential Improvements

  1. Iterative deepening: Search depth 1, then 2, then 3 until time runs out
  2. Transposition table: Cache evaluated positions to avoid re-computation
  3. Threat space search: Focus on forcing sequences
  4. Opening book: Pre-computed optimal opening moves
  5. Killer moves heuristic: Remember good moves from sibling nodes
