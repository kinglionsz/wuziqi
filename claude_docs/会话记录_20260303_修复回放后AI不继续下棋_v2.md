# 会话记录 - 修复回放后AI不继续下棋问题（第二次修复）

**日期**: 2026年3月3日
**问题**: 人机对战 - 回放 - 退出回放后，AI一直在思考中，没有继续下棋。如果点击棋盘变成了双人对战。

## 第一次修复的问题

第一次修复使用了 `flushSync` 和 `aiForceTriggerRef`，但存在问题：
1. `aiForceTriggerRef.current` 在依赖数组中不会正确触发 effect，因为 ref 的变化不会触发组件重新渲染
2. `flushSync` 虽然强制同步更新，但 React 的批量更新机制仍然可能导致时序问题
3. 用户测试后反馈：AI一直在思考中，完全不能继续下棋

## 最终解决方案

采用更直接的方法：添加一个 `triggerAiMove` 函数，直接触发 AI 落子，不依赖 React 的渲染周期。

### 修改内容

#### 1. src/hooks/useGameLogic.js

**添加 `triggerAiMove` 函数** (line:223-236):

```javascript
// 触发 AI 落子（用于退出回放等场景）
// 这个函数会直接调用 AI 落子逻辑，不依赖 React 的渲染周期
const triggerAiMove = useCallback(() => {
  // 如果是 AI 的回合且游戏未结束，则触发 AI 落子
  if (gameMode === GAME_MODES.PVE && currentPlayer === AI_PLAYER && !gameOver && !aiMoveRef.current) {
    aiMoveRef.current = true
    // 使用 setTimeout 给状态更新留出时间
    setTimeout(() => {
      const bestMove = findBestMove(board, AI_PLAYER, aiLevel)
      if (bestMove) {
        handleCellClick(bestMove.row, bestMove.col)
      }
      aiMoveRef.current = false
    }, 100)
  }
}, [gameMode, currentPlayer, gameOver, board, aiLevel, handleCellClick])
```

const exitReplay = useCallback(() => {
  // 先保存回放结束时的状态
  const lastMove = replayIndex >= 0 && replayIndex < moveHistory.length
    ? moveHistory[replayIndex]
    : null

  setGameOver(false)

    })

## 技术细节

### 为什么第一次修复失败？

1. **Ref 不会触发重新渲染**：`aiForceTriggerRef.current` 在依赖数组中不会触发 effect，因为 ref 的变化不会导致组件重新渲染。
2. **依赖数组的闭包陷阱**：即使 ref 的变化被检测到，effect 内部使用的可能是旧的闭包值。

### 为什么新方案有效？

1. **直接调用函数**：`triggerAiMove` 是一个普通的函数调用，不依赖 React 的渲染周期。
2. **使用 setTimeout 延迟**：给状态更新留出时间，确保 AI 计算时使用的是最新的棋盘状态。
3. **函数闭包捕获最新值**：`triggerAiMove` 使用 `useCallback` 包裹，并在每次渲染时重新创建，因此它捕获的是最新的状态值。

### 关键点

- `setTimeout` 的延迟时间（100ms）是经验值，可以根据实际情况调整
- `triggerAiMove` 内部检查所有必要条件（游戏模式、当前玩家、游戏状态等）
- `aiMoveRef` 用于防止 AI 重复落子
