针对 `kinglionsz/wuziqi` 项目中处于“开发中”的**在线对战 - 创建/加入房间**功能，五子棋的在线联机看似简单，但要做到稳定、无Bug且防作弊，需要处理大量的心跳、断线重连、状态同步等问题。

由于我无法直接修改你的本地代码，我将基于全栈开发标准（通常前端为 Vue/React/原生JS，后端推荐 Node.js + WebSocket/Socket.io），为你提供一套**从架构到代码实现的完整完善方案**。

---

### 第一阶段：核心架构设计 (WebSocket/Socket.io)

在线对战绝对不能使用 HTTP 轮询，必须使用 WebSocket。强烈推荐使用 **Socket.io**，因为它原生支持“房间 (Rooms)”概念，非常契合“创建/加入房间”的需求。

#### 数据结构设计（后端内存状态）
后端需要维护一个全局的房间对象来管理所有对局状态：
```javascript
const rooms = {
  "room_1234": {
    roomId: "room_1234",
    players: {
      "socketId_A": { role: 1, ready: false }, // 1 代表黑棋
      "socketId_B": { role: 2, ready: false }  // 2 代表白棋
    },
    board: [[]], // 15x15 的二维数组，记录棋盘状态
    currentTurn: 1, // 当前轮到谁下 (1 或 2)
    status: "waiting" // 状态：waiting(等待加入), ready(准备中), playing(对战中), finished(结束)
  }
}
```

### 第二阶段：后端逻辑完善 (Server-Side)

后端是游戏的大脑，**绝对不能信任前端传来的数据**，所有的落子合法性、胜负判断必须在后端进行或校验。

#### 1. 创建与加入房间逻辑
*   **创建房间 (Create Room):** 客户端发起请求，服务端生成唯一房间号（如4位或6位随机码），将该 Socket 设为房主（执黑），并加入 Socket.io 房间。
*   **加入房间 (Join Room):** 校验房间号是否存在、房间是否已满（2人）。如果合法，第二名玩家加入（执白），并广播 `game_start` 事件。

#### 2. 落子与状态同步 (Place Piece)
当玩家 A 落子时：
1.  **校验权限：** 检查当前 `currentTurn` 是否属于该玩家。
2.  **校验合法性：** 检查坐标 `(x, y)` 是否越界，以及该位置是否已有棋子。
3.  **更新状态：** 更新后端的 `board` 数组，切换 `currentTurn`。
4.  **胜负判定：** **后端**执行五子连珠算法，判断是否获胜。
5.  **广播数据：** 向房间内所有人广播最新棋盘状态和胜负结果。

### 第三阶段：前端逻辑完善 (Client-Side)

前端主要负责 UI 渲染和事件监听。

#### 1. 房间 UI 流程
*   **大厅界面：** 提供“创建房间”按钮和“输入房间号加入”的输入框。
*   **等待界面：** 房主创建后，显示“房间号：XXXX，等待对手加入...”。
*   **对战界面：** 双方到齐后，显示棋盘，提示“你是黑棋/白棋”。

#### 2. Socket 事件监听清单
前端需要监听以下核心事件：
*   `room_created`: 拿到房间号，切换到等待UI。
*   `join_success` / `join_error`: 处理加入成功或房间不存在/已满的错误提示。
*   `game_start`: 初始化棋盘，提示黑棋先手。
*   `sync_board`: 收到对手落子坐标，更新本地棋盘 UI，解除本地点击限制。
*   `game_over`: 收到游戏结束指令，弹出胜负结算框。
*   `opponent_disconnected`: 收到对手掉线提示。

### 第四阶段：关键代码示例 (Node.js + Socket.io)

**后端核心代码 (server.js)：**
```javascript
io.on('connection', (socket) => {
    // 1. 创建房间
    socket.on('create_room', () => {
        const roomId = Math.random().toString(36).substring(2, 6).toUpperCase();
        rooms[roomId] = {
            players: { [socket.id]: 1 }, // 1 为黑棋
            board: Array(15).fill(0).map(() => Array(15).fill(0)),
            currentTurn: 1,
            status: 'waiting'
        };
        socket.join(roomId);
        socket.emit('room_created', { roomId, role: 1 });
    });

    // 2. 加入房间
    socket.on('join_room', (roomId) => {
        const room = rooms[roomId];
        if (!room) return socket.emit('error', '房间不存在');
        if (Object.keys(room.players).length >= 2) return socket.emit('error', '房间已满');

        room.players[socket.id] = 2; // 2 为白棋
        room.status = 'playing';
        socket.join(roomId);
        
        // 告诉加入者成功了
        socket.emit('join_success', { roomId, role: 2 });
        // 通知房间所有人游戏开始
        io.to(roomId).emit('game_start', { turn: 1 });
    });

    // 3. 处理落子
    socket.on('place_piece', ({ roomId, x, y }) => {
        const room = rooms[roomId];
        if (!room || room.status !== 'playing') return;
        
        const playerRole = room.players[socket.id];
        // 防作弊：校验是否轮到该玩家，以及该位置是否为空
        if (room.currentTurn !== playerRole || room.board[x][y] !== 0) return;

        // 更新棋盘
        room.board[x][y] = playerRole;
        
        // 判断胜负 (需要你在后端实现 checkWin 函数)
        if (checkWin(room.board, x, y, playerRole)) {
            room.status = 'finished';
            io.to(roomId).emit('game_over', { winner: playerRole, x, y });
        } else {
            // 切换回合
            room.currentTurn = playerRole === 1 ? 2 : 1;
            io.to(roomId).emit('sync_board', { x, y, role: playerRole, nextTurn: room.currentTurn });
        }
    });
});
```

### 第五阶段：边界情况与体验优化 (进阶完善)

这也是“开发中”项目走向“成熟成品”必须要解决的问题：

1.  **断线重连机制 (极重要)：**
    *   **问题：** 玩家刷新页面或网络抖动，Socket ID 会变化，导致被踢出房间。
    *   **方案：** 客户端首次进入生成一个 `userId` (存入 LocalStorage)。连接 WebSocket 时带上 `userId`。后端将 `roomId` 与 `userId` 绑定，而不是仅仅绑定 Socket ID。玩家重连时，后端恢复其棋盘状态。
2.  **对手逃跑/掉线处理：**
    *   监听 `disconnect` 事件。如果对局中一方掉线，触发 `opponent_disconnected`。
    *   给掉线方 30 秒重连时间，若超时未连，直接判另一方获胜。
3.  **悔棋与求和功能：**
    *   增加 `request_undo` (申请悔棋) 事件，必须由对手发送 `agree_undo` 才能执行。
4.  **旁观者模式 (Spectator)：**
    *   如果房间已满（2人），后续加入的玩家分配角色 `0`（观众），只接收 `sync_board` 事件，不能触发 `place_piece`。
5.  **UI 交互防抖：**
    *   前端在自己落子后，立刻锁定棋盘（`pointer-events: none`），直到收到后端的 `sync_board` 且 `nextTurn` 是自己时才解锁，防止连续点击发送多次落子请求。
